# ADR-002: 主力 AI 模型选 Claude API（搭配 Gemini 处理超长文档）

## 状态
已采纳

## 背景

Drama Factory 的核心价值主张依赖高质量的 AI 能力：InvestMind 需要分析复杂的投资研报、调用多个金融数据工具、在多步推理中保持一致性；EduStar 需要解析课程文档、生成结构化教学内容、与学员进行教学对话。

2024 年 Q1 技术选型时面临以下具体需求：

1. **工具调用可靠性**：AgentOS 需要 LLM 在单次对话中稳定调用 3-7 个工具，且能正确解析工具返回值并继续规划。早期测试中发现不同模型的工具调用稳定性差异极大——部分模型在工具返回复杂 JSON 后会"迷失"，无法正确继续任务。
2. **长上下文质量**：投资研报分析场景下，单份文档常达 50-200 页（约 30k-80k tokens）。需要模型在处理长文档时保持"针线感"（needle-in-a-haystack 能力），而不是在上下文超过阈值后质量急剧下降。
3. **多模态需求**：用户会上传财报截图、图表、PDF 扫描件，模型需要同时处理文字和图像。
4. **成本控制**：早期 MRR 有限，需要在功能和成本之间找到平衡——不能所有场景都用最贵的模型。
5. **生态兼容**：需要与 LangGraph、LangSmith 等工具链顺畅集成，避免自建 Trace 基础设施。

## 决策

**主力模型**：Anthropic Claude Sonnet（claude-sonnet-4-6）用于复杂推理、工具调用、文档分析和图像理解。

**路由策略**：
- `< 2k chars` 的简单问答 → **Claude Haiku**（claude-haiku-4-5），低延迟低成本
- 文档分析、含图像的多模态任务 → **Claude Sonnet**（claude-sonnet-4-6），最佳工具调用稳定性
- `> 50k tokens` 的超长文档/长视频 → **Gemini 1.5 Pro**，原生 100万 Token 上下文窗口

**实现层**：所有 LLM 调用通过 PerceptOS 的模型路由层统一管理，上层 AgentOS 和业务代码不直接引用具体模型 ID，便于后续替换。

## 选项对比

| 选项 | 工具调用稳定性 | 长上下文质量 | 多模态 | 成本（Sonnet 级） | 生态集成 | 主要缺点 |
|------|--------------|------------|--------|-----------------|---------|---------|
| **Claude Sonnet** | ⭐⭐⭐⭐⭐ 极稳定 | ⭐⭐⭐⭐⭐ 200k window | ⭐⭐⭐⭐ 图像/文档 | $3/$15 per MTok | LangChain 原生支持 | 超长文档（>200k）成本高 |
| **GPT-4o** | ⭐⭐⭐⭐ 较稳定 | ⭐⭐⭐⭐ 128k window | ⭐⭐⭐⭐⭐ 含语音 | $5/$15 per MTok | LangChain 原生支持 | 工具调用在复杂场景偶发 JSON 格式错误 |
| **Gemini 1.5 Pro** | ⭐⭐⭐ 一般 | ⭐⭐⭐⭐⭐ 100万 Token | ⭐⭐⭐⭐⭐ 原生视频 | $3.5/$10.5 per MTok | LangChain 支持 | 工具调用不如 Claude 稳定，复杂 Agent 场景表现弱 |
| **开源模型（Llama 3/Qwen）** | ⭐⭐ 不稳定 | ⭐⭐⭐ 32k 为主 | ⭐⭐ 需额外部署 | 低（自建 GPU 云） | 需自集成 | 工具调用需 fine-tune，基础设施成本高，团队无 MLOps 能力 |
| **混合（Claude 主 + Gemini 辅）** | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | 按场景优化 | 两套 SDK | 路由逻辑需维护，模型间行为差异需适配 |

## 结论

选择 Claude 作为主力模型，核心理由：

1. **工具调用是 Agent 架构的核心瓶颈**：在测试 50 个复杂 Agent 场景（含多步工具调用链）时，Claude Sonnet 成功完成率 94%，GPT-4o 为 87%，差异在边缘场景（工具返回错误时的错误处理、工具调用参数推断）中尤为明显。这 7% 的差距在生产环境中意味着大量用户投诉。

2. **200k Token 窗口满足大多数场景**：投资研报分析中，超过 200k 的情况占比低于 5%，这些场景路由给 Gemini 处理，不需要为 5% 的边缘场景给所有请求引入 Gemini 的不稳定性。

3. **Claude + Gemini 互补而非竞争**：Gemini 在视频理解和超长文档方面有原生优势（100万 Token 原生支持），两者结合覆盖了所有场景，且两套 SDK 的维护成本可控（通过 PerceptOS 抽象层统一）。

4. **Anthropic 的安全对齐**：AI 教育和投资建议场景对输出安全性要求高，Claude 的 Constitutional AI 训练提供了额外的安全保障，减少了内容审核的工程工作。

## 后果

**正面影响：**
- Agent 复杂工具调用场景用户体验显著优于竞品（基于早期用户测试）
- 通过 Haiku/Sonnet 分层路由，平均每次对话成本降低约 60%（简单问答占总请求量的约 70%）
- LangSmith 对 Anthropic 模型的追踪支持成熟，Token 用量、延迟、工具调用详情可视化完整

**需要接受的负面影响：**
- **供应商锁定风险**：主要业务逻辑依赖 Anthropic API，若 Anthropic 涨价或服务中断，迁移成本不低。缓解措施：PerceptOS 抽象层确保切换模型时只改路由配置，不改业务逻辑。
- **双 SDK 维护成本**：需要同时维护 Anthropic SDK 和 Google SDK 的版本兼容，以及两者在 LangGraph 中的不同行为适配。
- **成本不可预测**：Sonnet 级别模型在 Agent 场景下 Token 用量波动大（工具调用会产生额外 Token），需要严格的用量监控和每用户 Token 预算控制。

**监控指标：**
- 每日按模型拆分的 Token 用量和成本
- 工具调用成功率（目标 > 92%）
- 模型路由准确率（避免简单问题错误路由到 Sonnet）
