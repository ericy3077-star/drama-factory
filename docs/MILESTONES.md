# 项目里程碑计划

**版本**：v0.1  
**最后更新**：2026-05-22  
**负责人**：Tech Lead + Product Team

---

## 全局说明

三个阶段的目标是层层递进的：Phase 1 证明产品可以卖、Phase 2 证明两个产品可以协同，Phase 3 证明有网络效应。每个阶段结束时都有明确的"不达标则不进入下一阶段"的门控条件（Go/No-Go）。

**工程资源假设**：2名全栈工程师 + 1名兼职 DevOps，0.5名产品/设计。实际资源不同时，优先级不变，时间线相应调整。

## Phase 1：InvestMind MVP（第1-8周）

### 目标

上线可付费的 InvestMind，获取前50个真实付费用户，月收入达到 ¥1万（验证付费意愿，非追求规模）。

**Go/No-Go 门控**：第8周结束时，若付费用户 < 10人，则暂停 Phase 2，重新梳理 InvestMind 产品定位，不贸然铺摊子。

### Week 1-2：基础设施

**目标**：所有后续功能的基础底座搭好，后续开发不需要回头补基础。

- [ ] **数据库 Schema 初始化**：执行 `migrations/001_initial_schema.sql`，验证所有核心表（`users`, `memories`, `avatars`, `courses`, `lessons`, `learner_events`, `research_notes`, `watchlists`）已创建，向量索引 `pgvector` 扩展已启用
- [ ] **RLS 策略完整验证**：为每张核心表编写 RLS 策略，并通过自动化测试验证（用 User A 的 JWT 无法查询 User B 的数据，返回空集而非403，符合 Postgres RLS 行为）
- [ ] **用户注册/登录流程**：邮箱注册（含邮件验证）、密码登录、JWT 签发与刷新（Access Token 15分钟过期，Refresh Token 30天）、密码重置（邮件链接）
- [ ] **前端认证流程**：登录/注册页面、Token 自动刷新逻辑、未登录时路由守卫（重定向至 `/login`）、登录后跳转至 `/invest/dashboard`
- [ ] **CI/CD 流水线**：GitHub Actions 配置——PR 时跑单元测试（后端 pytest / 前端 jest）、main 分支 push 后自动部署至 staging 环境；部署失败时 Slack 告警（或邮件）
- [ ] **环境变量规范**：`.env.example` 更新为所有需要配置的变量，本地开发文档更新，新成员 clone 后 30 分钟内可以把环境跑起来

**验收标准**：新成员按文档操作，30分钟内本地环境完整运行；RLS 自动化测试全部通过；CI 在 PR 上成功运行。

**风险**：Supabase RLS 与 SQLAlchemy 的兼容性——Supabase 使用 `anon` 和 `authenticated` 角色，后端 ORM 需要在每次请求时设置 `SET LOCAL role = authenticated; SET LOCAL request.jwt.claim.sub = 'user_id'`，否则 RLS 不生效。这个模式需要在 Week 1 验证清楚，不要等到 Week 7 上线前发现。

### Week 3-4：信息流 MVP

**目标**：用户注册后能看到真实的 AI 信息流，这是产品的第一个"WOW 时刻"。

- [ ] **东方财富 RSS 接入**：`feed_worker.py` 接入东方财富新闻 RSS（`https://feed.eastmoney.com/news/1,0.html` 等），解析 XML，去重存入 `research_notes` 表
- [ ] **新浪财经 RSS 接入**：同上，接入新浪财经实时新闻 RSS
- [ ] **A股公告爬虫**：上交所（`http://www.sse.com.cn/disclosure/`）+ 深交所（`https://www.szse.cn/disclosure/`）公告爬虫，每30分钟抓取一次，提取公告标题/发布时间/PDF链接/股票代码
- [ ] **AI 日报生成任务**：每日 06:30（北京时间）触发定时任务，将前24小时公告按用户关注行业过滤，调用 `claude-haiku-4-5` 生成日报（≤500字摘要 + 逐条简评），结果缓存，所有同行业用户共享同一份日报（节省 token 成本）
- [ ] **PerceptOS 单条公告深度解析**：接入 `PerceptOS` 的文档理解能力，用户点击"深度解析"时，下载 PDF 并用 `claude-sonnet-4-6` 进行结构化解析，结果缓存24小时
- [ ] **前端信息流界面**：`FeedCard` 组件（标题/来源/发布时间/摘要/情感标签），信息流页面（无限滚动或分页），深度解析侧边面板（Drawer），个人信息流偏好设置页

**验收标准**：在产品环境中，注册一个新用户，设置关注行业为"新能源"，次日 07:30 前看到包含新能源相关内容的 AI 日报；点击任意公告"深度解析"，10秒内返回结构化内容（允许首次解析慢，后续缓存）。

**风险**：
- 公告网站反爬限制——深交所/上交所偶尔限制爬虫频率。应对策略：添加随机延迟（0.5-2秒），使用合理的 User-Agent，设置重试队列而非直接失败。
- HuggingFace 或阿里云 NLP 情感分析的准确率——金融情感分析不同于通用情感，"利润下滑30%"情感标签应是"负面"，而不是中性。建议直接用 Claude 做情感分类，而非调用专门情感模型，成本可控。

### Week 5-6：对话助手

**目标**：用户可以用自然语言问关于投资的问题，AI 回答有记忆、有来源。

- [ ] **MemoryOS 基础版**：实现 `store(user_id, content, metadata)` 和 `recall(user_id, query, top_k=5)` 两个核心接口。`store` 调用 Embedding API（推荐 OpenAI `text-embedding-3-small`）生成向量并存入 `memories` 表；`recall` 用余弦相似度检索，返回 top-k 结果
- [ ] **AgentOS 基础版**：基于 LangGraph 实现单步工具调用的 Agent 状态机。工具集：`search_documents`（搜索用户已上传文档）、`recall_memory`（调用 MemoryOS）、`get_feed_item`（获取信息流条目详情）。不实现复杂的多步规划，Week 5-6 只要能稳定调用1个工具就算成功
- [ ] **SSE 流式对话接口**：`POST /api/v1/chat/stream`，Server-Sent Events，每个 Token 一个 `data:` 事件，工具调用开始时发送 `event: tool_call`，工具调用结束时发送 `event: tool_result`，对话结束时发送 `event: done`
- [ ] **前端 ChatAssistant 对接后端**：替换现有的 Mock 数据为真实 SSE 流，处理工具调用事件（渲染折叠的工具调用卡片），处理网络断开时的重连逻辑
- [ ] **对话历史持久化**：会话（`sessions`）和消息（`messages`）存入数据库，前端侧边栏显示历史会话列表，点击可恢复对话上下文。消息存储时同时 `store` 到 MemoryOS（选择性地存，只存用户的关键问题，不存所有 AI 回复）

**验收标准**：
1. 用户问"帮我查一下我上传的那份宁德时代年报里的研发投入"，AI 能正确调用 `search_documents` 并引用具体页码回答
2. 隔天问"上次说的宁德那个研发数据"，AI 能从 MemoryOS 检索到昨天的对话并回答
3. 流式回复在手机网络（4G）下无卡顿，首字出现时间 < 2秒

**风险**：
- LangGraph 的 `stream` 模式与 FastAPI SSE 的集成——LangGraph 的 `astream_events` 接口与 FastAPI 的 `StreamingResponse` 的集成有坑，需要处理异步生成器的异常传播，防止 Agent 内部报错但 SSE 连接不关闭
- MemoryOS 的召回精度——向量相似度召回在早期用户数据少时可能返回不相关内容，需要设置相似度阈值（如余弦相似度 > 0.75 才返回），低于阈值时返回空，而不是强行返回低质量结果

### Week 7-8：上线准备

**目标**：产品可以正式对外收费运营，有基本的安全和可观测性保障。

- [ ] **Stripe 订阅支付接入**：创建 Stripe 产品和价格（月付专业版，年付专业版），前端集成 Stripe Checkout（不自己实现支付表单），Webhook 接收 `checkout.session.completed` 和 `customer.subscription.deleted` 事件，更新用户订阅状态
- [ ] **Webhook 签名验证**：Stripe Webhook 必须验证 `Stripe-Signature` 头，防止伪造支付事件。用独立的 `/api/stripe/webhook` 路由处理，不经过认证中间件（Stripe 不带 JWT）
- [ ] **用量限额中间件**：在 `/api/v1/chat/stream` 和 `/api/v1/documents/parse` 入口添加用量检查中间件。免费用户：每日5次对话（按自然日重置），每月10次文档解析。付费用户：对话不限，文档100次/月。超限时返回 HTTP 429，body 中包含剩余额度和下次重置时间
- [ ] **错误监控（Sentry）**：后端集成 Sentry Python SDK，前端集成 Sentry React SDK。设置告警规则：同一异常5分钟内出现10次以上，发送邮件告警。LLM 调用的 token 超限/API 限速错误单独分类，不算作"产品错误"
- [ ] **LangSmith AI 调用追踪**：所有 Claude/Gemini 调用包装在 LangSmith Trace 中，记录：prompt template 名称、token 用量（input/output/cache）、时延、用户ID（不记录具体内容，注意隐私）
- [ ] **性能测试（并发10用户）**：用 Locust 模拟10个并发用户同时发送对话请求，验证系统在负载下：无崩溃、平均首字时延 < 3秒（允许负载下稍慢）、错误率 < 1%
- [ ] **隐私协议 + 金融免责声明**：上线前必须有可访问的隐私政策页面（`/legal/privacy`）和服务条款页面（`/legal/terms`）；AI 生成的所有投资相关内容末尾自动附加免责声明，这是合规硬要求

**验收标准**：
1. 完整的"注册→Onboarding→升级专业版（Stripe付款）→使用高级功能"流程，在3台不同设备上无报错跑通
2. Stripe 测试模式下，模拟付款成功 → 用户权限在5秒内升级
3. Sentry Dashboard 可以看到错误上报（用一个测试请求故意触发500错误验证）
4. LangSmith 中可以看到所有 AI 调用的 Trace（打开一个对话，在 LangSmith 中找到对应的 Trace）

**风险**：
- Stripe 在国内的访问速度——Stripe 的 JS SDK 加载有时在国内较慢，需要测试实际加载时间，必要时考虑 Stripe 的香港/新加坡节点
- 性能测试暴露的意外瓶颈——10并发测试可能暴露数据库连接池不足的问题，确保 `asyncpg` 连接池配置合理（建议 min=5, max=20）

### Week 9-12：AvatarOS + EduStar MVP

**目标**：完成数字人核心链路——从素材上传到视频生成，全流程跑通。

- [ ] **HeyGen API 集成测试**：在测试环境中验证 HeyGen 的三个核心 API：`POST /v2/avatars/`（创建数字人训练任务）、`GET /v2/avatars/{avatar_id}`（查询训练状态）、`POST /v2/videos/`（生成视频）。编写集成测试用例，覆盖成功路径和 API 限速场景
- [ ] **素材上传流程**：前端实现分片上传（使用 `tus` 协议或自实现分片），支持断点续传，进度条显示。后端接收完成后触发 PerceptOS 质检任务，质检结果通过 WebSocket 推送给前端
- [ ] **素材质检服务**：在 `AvatarOS` 中实现质检逻辑：使用 `ffprobe` 检查分辨率/帧率/时长，使用 `mediapipe` 或 AWS Rekognition 检查人脸清晰度和背景，生成结构化质检报告
- [ ] **异步生成任务队列**：使用 `Celery + Redis` 实现 `avatar_worker` 的任务队列（或验证是否使用现有的 worker 方案，避免重复造轮子）。任务状态：`pending → running → succeeded / failed`。失败时保留错误信息，支持重试
- [ ] **WebSocket 任务状态推送**：前端通过 WebSocket 订阅任务状态更新（`/ws/tasks/{task_id}`）。后端任务状态变更时，向对应 WebSocket 连接推送状态 JSON。用户关闭页面后重新打开，WebSocket 重连后自动获取最新状态
- [ ] **前端 AvatarStudio 对接**：`/edu/avatar-studio` 路由，包含：素材上传区域（含拍摄指南）、质检结果展示、训练状态追踪、我的数字人列表（训练完成的数字人缩略图 + 示例视频预览）

**验收标准**：
1. 上传一份符合规范的素材视频，完整走完"上传→质检通过→提交训练→WebSocket收到完成通知→预览示例视频"流程，全程不需要刷新页面
2. 上传一份不符合规范的素材（如纵向视频），质检报告正确标记"不合格"并给出具体原因
3. 模拟 HeyGen API 返回限速错误（429），任务进入"自动重试中"状态，2次重试后成功

**风险**：
- HeyGen 训练时间不稳定——HeyGen 训练一个数字人需要1-24小时（视队列情况），这意味着"用户当天提交，当天看到结果"的体验无法保证。产品侧需要明确告知用户预期等待时间（48小时内），不要给用户造成"卡住了"的误解。WebSocket 的心跳机制需要正确处理长时间连接
- Celery + Redis 的运维成本——引入 Celery 需要额外的 Redis 实例和 Celery Worker 进程管理，增加 DevOps 复杂度。如果团队资源紧张，可以先用 FastAPI 的 `BackgroundTasks` 替代，接受并发任务数受限的缺陷，后续再迁移到 Celery

### Week 13-16：AI 课程工厂

**目标**：讲师从主题到视频全流程自动化，这是 EduStar 的核心价值主张。

- [ ] **AI 大纲生成（AgentOS）**：在 `AgentOS` 中实现多步骤大纲生成工具链：Step 1 - 接收课程主题和目标受众（必填）；Step 2 - 联网检索相关知识点（Tool: Web Search，可选）；Step 3 - 生成3级大纲（章节/小节/知识点），输出 JSON + 前端渲染的树形结构。大纲生成使用 `claude-sonnet-4-6`，完整大纲生成时间 < 30秒
- [ ] **分节脚本批量生成**：用户确认大纲结构后，可以选择全部节次或部分节次批量生成脚本。每节脚本生成为独立的 AgentOS 任务，并行执行（最多8个并行），前端展示生成进度（X/N 节完成）。脚本格式：主讲文字 + 演示说明（如"此处切换PPT第3页"）
- [ ] **脚本风格调整**：每节脚本生成后，支持"风格重写"：口语化（适合视频讲解）、书面化（适合文档分发）、互动版（添加提问和互动环节）。风格重写调用 `claude-haiku-4-5`（成本控制），时间 < 10秒/节
- [ ] **批量视频生成流水线**：用户确认脚本后，点击"全部生成视频"，系统将每节脚本提交到 HeyGen，创建对应的视频生成任务。任务列表页显示整门课程的生成进度矩阵（每节一格，颜色代表状态：待生成/生成中/完成/失败）
- [ ] **课程管理界面**：`/edu/courses` 路由，课程列表 + 新建课程入口；课程详情页包含大纲树和每节的脚本/视频状态；支持手动排序节次（拖拽）；支持单节脚本编辑和重新生成视频

**验收标准**：
1. 输入课程主题"Python 入门：零基础到第一个程序"，30秒内生成包含6-8节的3级大纲
2. 确认大纲后，批量生成8节脚本，全部完成时间 < 5分钟（并行生成）
3. 提交8个视频生成任务，任务列表页实时显示生成进度，无需刷新

**风险**：
- 脚本质量的主观性——AI 生成的脚本对于某些专业性强的课程（如医学、法律）质量不稳定。产品策略：不设自动发布，所有脚本必须讲师审核确认后才能提交生成视频，不做"一键无人工干预"的功能
- HeyGen 批量任务的并发成本——同时提交8个视频任务，HeyGen 按任务收费，需要在前端明确告知即将消耗的配额数量，让用户有意识地控制成本

### Week 17-20：学习平台 + 数据打通

**目标**：学员可以在 EduStar 平台上学习课程，两个产品的用户数据开始共享，建立数据飞轮基础。

- [ ] **学习平台播放器**：基于 `Video.js` 或 `Plyr` 实现课程播放器，功能：倍速播放（0.5x-2x）、字幕开关、键盘快捷键（空格/左右箭头）、清晰度切换（如果 CDN 支持）。播放进度实时存储（每10秒上报一次），关闭后下次打开自动续播
- [ ] **learner_events 数据采集**：定义事件类型并埋点：`video_play`、`video_pause`、`video_complete`（观看≥90%）、`video_seek`（跳跳党行为追踪）、`chapter_start`、`quiz_answer`（为后续互动功能预留）。事件异步上报（不阻塞播放体验）
- [ ] **InvestMind ↔ EduStar 用户数据共享（MemoryOS）**：实现跨产品的 MemoryOS 共享：用户在 InvestMind 中积累的研究记录，在 EduStar 的"推荐课程"模块中用于个性化推荐（如：InvestMind 用户频繁研究新能源 → EduStar 推荐新能源投资分析课程）。技术实现：`recall` 接口增加 `namespace` 参数，支持跨命名空间检索（需要用户授权开启跨产品数据共享）
- [ ] **数据分析看板（讲师视角）**：`/edu/analytics` 路由，展示：课程整体完课率、每节完课率热力图（哪节流失最多）、学员学习时长分布、活跃学员列表。数据通过 `learner_events` 聚合，每小时刷新一次（非实时，用于降低数据库压力）
- [ ] **学员管理**：课程购买流程（Stripe）、讲师查看学员列表（邮箱/付费时间/学习进度）、学员可查看自己的购课记录和学习证书（系统自动生成证书 PDF，完课率100%时解锁）

**验收标准**：
1. 学员购买一门课程，观看至第3节，关闭浏览器，再次打开，从第3节中断位置继续播放
2. 讲师查看数据看板，能看到每节课的完课率和流失节点（需要至少3个学员有真实学习记录才有意义）
3. InvestMind 用户开启跨产品共享后，EduStar 推荐页面出现与其 InvestMind 研究主题相关的课程推荐

**风险**：
- 跨产品数据共享的隐私合规——用户的研究记录属于敏感数据，跨产品共享必须经过明确的用户授权（不是默认开启）。授权入口要清晰，授权说明要诚实（"你在 InvestMind 的研究主题将用于在 EduStar 推荐相关课程"），不要藏在隐私政策小字里
- 数据分析看板的聚合查询性能——`learner_events` 表在数据量大时聚合查询很慢，从一开始就按 `course_id` 和 `date` 做分区，并创建对应索引，避免日后数据迁移

## Phase 3：平台化（第21周+）

### 目标

双产品网络效应启动，引入供需双边平台机制，平台 GMV > ¥100万/月。核心标志：用户不只是消费平台内容，也开始在平台上生产内容并获得收益（AI 员工市场）。

---

### 战略任务（无固定周次，按资源和市场验证节奏推进）

- [ ] **AI 员工市场（供需双边）**：InvestMind 分析师可以发布自己的研究模板（如"科技行业竞争分析框架"）供其他用户购买使用；EduStar 讲师可以发布课程模板和数字人出租服务。平台抽佣20%，其余归内容创作者
- [ ] **PerceptOS 对外 API（开发者市场）**：将 PerceptOS 的多模态文档理解能力以 API 形式对外开放（类似 OpenAI API），开发者调用付费。主要应用场景：金融机构自建研报解析系统、律所合同分析工具。需要单独的开发者控制台、API Key 管理、用量计费
- [ ] **企业版私有化部署包**：打包成可以部署在客户自有云（阿里云/腾讯云私有化）的 Docker Compose / Helm Chart。包含：全量后端服务、Postgres + pgvector、Redis、Nginx。需要专门的企业授权机制（License Key）
- [ ] **多语言克隆（EduStar 海外版）**：在已有数字人基础上，支持讲师选择目标语言，系统自动翻译脚本并生成对应语言的数字人视频（HeyGen 支持多语言 TTS）。支持语言：英文、日文、泰文、越南文（按市场需求优先级）
- [ ] **Wind / 彭博数据接入（InvestMind 机构版）**：接入 Wind API（国内机构投研主力数据源），提供实时行情、历史财务数据、研究报告数据。这是机构用户付费的核心驱动，定价策略与 Wind 数据授权成本绑定。同时评估彭博 BSKT API 接入可行性
