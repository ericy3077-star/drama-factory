## 1. 产品愿景

### 一句话定位

> **InvestMind 是投资从业者的 AI 超级助手——让一个分析师的产出等于三个。**

### 核心问题

投资研究的本质是在信息过载中找到真正的 Alpha。当前分析师每天花 3-4 小时盯公告、读财报、整理会议纪要，真正用于深度思考和建立投资逻辑的时间不足 30%。InvestMind 解决的不是"分析师不够聪明"的问题，而是**信息处理的摩擦成本太高**这个结构性问题。

我们不做另一个 ChatGPT Wrapper。InvestMind 的护城河在于：持续积累的用户投资记忆（MemoryOS）、跨文档的关联推理能力（AgentOS）、以及垂直于金融场景的工具链。三个月后，用户的 InvestMind 已经"认识"他的投资风格、持仓偏好、历史研究，这种积累是竞争对手无法复制的。

## 2. 目标用户（Personas）

### P1：私募基金分析师（主力用户）

**人口属性**：25-35岁，CFA/FRM持证或在考，985/211本硕，集中在北上深私募聚集地。

**工作场景**：
- 每天早上7:30前需要看完隔夜海外市场 + A股公告，在晨会前形成观点
- 每周至少产出1-2份深度研报或投资备忘录，字数3000-8000字
- 同时跟踪5-15个行业、30-100个标的
- 频繁处理上市公司PDF年报（100-500页）、招股书、专项审计报告

**核心痛点**：
1. **信息聚合成本高**：散落在东财、Wind、公司官网、微信群的信息，每天需要人工汇总
2. **文档阅读耗时**：一份300页年报读完关键信息需要2小时，季报密集期压力极大
3. **研究成果难沉淀**：OneNote/有道云写的研究笔记和 Bloomberg Terminal 的数据完全割裂
4. **知识传承断层**：老分析师离职，研究积累全带走，团队要重新建仓位逻辑

**使用频次**：工作日每天打开，高峰在晨会前（7-9点）和收盘后（3-5点）。

**付费预期**：个人付费能力有限（公司通常不报销），期望个人版 ¥200-500/月。如果功能真的节省2小时/天，ROI 极高，愿意自掏腰包。内推文化强，一个分析师带一个部门。

---

### P2：独立投资顾问（高价值用户）

**人口属性**：35-50岁，券商/公募背景出身，转型做独立顾问或买方策略师，管理 HNW 客户或合伙制小基金（1-10亿规模）。

**工作场景**：
- 独立运营，没有研究团队支持，一个人承担研究+客户服务+合规
- 客户要求定期（月/季度）提供个性化投研报告
- 需要快速对客户提问形成有据可查的书面回复（合规留痕）
- 参与路演、电话会，需要提前快速了解公司基本面

**核心痛点**：
1. **一个人干三个人的活**：既要研究，又要写报告，还要回客户消息，时间极度碎片化
2. **客户个性化需求高**：A客户关注新能源，B客户关注消费，C客户要求季度回顾，很难标准化
3. **合规压力**：投资建议必须有来源支撑，随口说的话事后说不清楚
4. **知识碎片化**：调研记录、电话会纪要散落各处，想复盘时找不到

**使用频次**：每天使用，但使用模式更碎片化——上午研究、下午见客户、晚上整理报告，在三种模式间快速切换。

**付费预期**：专业用途，付费意愿强，个人版 ¥500-1000/月。如果有助于获客/留客，间接ROI更高。

---

### P3：高净值个人投资者（成长用户）

**人口属性**：35-55岁，主业为企业主/高管/专业人士，可投资资产500万+，自主管理部分股权投资，非全职投资。

**工作场景**：
- 每天利用碎片时间（通勤、午休）了解市场
- 有一定研究能力，能读财报，但时间不够
- 关注少数几个重仓行业（通常与自己主业相关）
- 有时需要就某个投资决策做"尽职调查"

**核心痛点**：
1. **信息不对称**：读到的信息比专业机构慢，质量参差不齐，被噪音干扰
2. **缺少研究框架**：知道看ROE、PE，但不知道怎么把碎片信息串成投资逻辑
3. **验证想法耗时**：有了某个投资想法，要自己确认需要花半天查资料
4. **没有记忆的助手**：现有的AI工具每次都要重新介绍自己的投资偏好

**使用频次**：每天1-2次，非高强度，主要在信息消费和想法验证两个场景。

**付费预期**：消费级定价更敏感，¥99-299/月区间可接受，但功能门槛相对低，对"看起来专业"有一定需求（说服自己和配偶）。

## 3. 用户旅程

### Stage 0：种草（Day -30 ~ Day 0）

**触点**：
- 雪球/知乎的"AI如何辅助投研"类文章（P1/P2 主要渠道）
- 同事/朋友内推（最高质量来源，私募圈子小，口碑传播快）
- 微信公众号"AI+金融"内容分发
- 搜索"AI读财报"、"AI信息流"等关键词

**用户心理**：半信半疑。"又一个AI工具？之前用过几个，都是噱头大于实际。" 转化点在于**具体场景的颗粒度**，不是说"AI帮你投资"，而是"30秒生成一份600字的公告解读，包含影响评级"。

---

### Stage 1：注册（Day 0）

**关键动作**：访问官网 → 看Landing Page → 注册（邮箱/手机）→ 免费额度激活

**摩擦点与解法**：
- 摩擦：不知道是否值得填信息 → 解法：Landing Page 放真实输出样例（真实财报AI解读截图）
- 摩擦：担心收费 → 解法：明确标注"免费版含每天5次对话+3份文档解析"
- 摩擦：填写信息太复杂 → 解法：只要求邮箱+密码，职业信息onboarding时收集

**目标转化率**：Landing Page → 注册 ≥ 15%

---

### Stage 2：Onboarding（Day 0-3）

用户完成注册后进入**引导式Onboarding**，而不是直接扔进一个空白界面。

**Step 1 - 职业画像**（30秒）：选择角色（私募分析师 / 独立顾问 / 个人投资者 / 其他）、主要关注行业（多选）、目前最头疼的研究场景（多选）。这些数据用于个性化信息流和推荐功能。

**Step 2 - 信息流配置**（2分钟）：系统根据行业选择预填RSS源，用户可修改。第一次配置完毕后，立即触发一次信息流抓取，**10分钟内看到第一条AI日报**。这是激活时刻（Aha Moment）的关键——用户必须在注册当天看到具体的价值输出。

**Step 3 - 上传第一份文档**（可选，引导完成）：提示"上传一份你最近在研究的PDF财报，体验AI解析"。完成者留存率显著高于未完成者。

**激活标准（7日留存基准）**：完成信息流配置 + 收到第一条AI日报的用户，7日留存率目标 ≥ 60%。

---

### Stage 3：初步使用（Day 3-14）

**高频行为**：
- 每天打开看 AI 信息流日报（被动消费，低阻力）
- 遇到感兴趣的公告，点击"深度解析"
- 开始用对话助手问一些具体问题（"帮我解释这份财报里的商誉减值"）

**流失风险点**：
- 信息流内容质量不稳定（重复/无关信息）→ 需要持续优化抓取和过滤规则
- 对话助手回答太泛，没有利用用户上下文 → MemoryOS 需要在第一周就建立基础用户画像
- 免费配额用完，没有明确的续费理由 → 在用完前提示具体的付费价值（"你本周节省了X小时"）

---

### Stage 4：付费转化（Day 7-30）

**转化触发点**：
1. **自然触发**：免费配额耗尽时（最常见）
2. **价值触发**：使用某个付费功能（如多文档对比）时提示升级
3. **时间触发**：注册第7天发送"你的第一周使用报告"邮件，包含具体数字（处理了X份文档，节省约Y小时）

**定价策略**（详见商业化文档，这里定性描述）：
- 免费版：每天5次对话，每月10份文档，基础信息流
- 专业版（月付）：无限对话，100份/月文档，完整Agent功能
- 团队版（年付）：多席位，共享知识库

**目标转化率**：注册用户 → 付费用户 ≥ 8%（第一年目标，通过优化提升至15%）

---

### Stage 5：深度使用（Day 30+）

**深度用户特征**：
- 主动上传文档建立自己的知识库（MemoryOS 积累明显）
- 使用研究工作台生成投资备忘录
- 开始依赖 AI 日报作为晨会前的必备工作流

**留存飞轮**：用得越多，MemoryOS 积累越丰富 → AI 回答越个性化、越准确 → 越难迁移到其他工具 → 续费率越高。这是产品的核心壁垒。

**续费率目标**：月付用户月续费率 ≥ 75%，年付用户年续费率 ≥ 70%。

---

### Stage 6：口碑传播（Day 60+）

**主要渠道**：
- 部门内推：分析师向同组同事推荐（私募内部工具共享文化强）
- 社区分享：雪球/知乎晒AI生成的分析截图（需要配合"分享"功能设计，输出物要好看）
- 主动邀请：邀请制福利（被邀请人获得额外免费配额）

**NPS 目标**：≥ 50（Deep user group，非全量）

## 5. P0 功能用户故事与验收标准

### 5.1 智能信息流

**用户故事**

> 作为私募分析师，我希望每天早上7:30收到一份AI整理的投资信息日报，以便在晨会开始前30分钟内掌握隔夜重要事件，不遗漏重大公告。

**验收标准（AC）**：

1. **AC-1 数据源覆盖**：系统默认接入东方财富、新浪财经 RSS，以及上交所、深交所公告官网。用户可在设置页新增自定义 RSS URL，添加后5分钟内生效。
2. **AC-2 日报生成时效**：每日 07:00（北京时间）前完成前一日全量公告的 AI 提炼，用户打开应用即可看到当日日报，不需要等待。
3. **AC-3 日报内容质量**：日报包含三部分——重大事件摘要（≤500字）、单条公告简评列表（每条≤80字）、市场情绪指数（正面/中性/负面）。每条简评必须标注来源公告链接。
4. **AC-4 个性化过滤**：日报内容根据用户在 Onboarding 时选择的关注行业进行过滤排序，用户关注行业的内容优先展示在前；无关行业内容可折叠。
5. **AC-5 深度解析触发**：用户点击任意公告条目的"深度解析"按钮，5秒内返回一份结构化解读（公司基本信息、事件描述、潜在影响分析、需关注的后续指标），使用 claude-sonnet-4-6 模型。

---

### 5.2 文档解析

**用户故事**

> 作为独立投资顾问，我希望上传一份上市公司 PDF 年报后，AI 自动提取核心财务指标和管理层讨论要点，以便我在与客户通话前的10分钟内完成快速尽调，不需要从头翻阅300页原文。

**验收标准（AC）**：

1. **AC-1 文件格式支持**：支持 PDF、Word（.docx）格式，单文件大小限制50MB，页数限制500页。超限时给出明确错误提示和建议（如"请上传核心章节"）。
2. **AC-2 解析时效**：100页以内文档，解析完成时间 ≤ 60秒；100-300页文档 ≤ 3分钟。解析期间显示进度条，完成后发送站内通知。
3. **AC-3 财报结构化输出**：对于上市公司年报/季报，输出必须包含：营收及同比增长、净利润及同比增长、经营现金流、资产负债率、管理层十大关键表述（从"管理层讨论与分析"章节提取）。
4. **AC-4 跨文档引用**：用户在对话中提问时，可通过 "@文档名" 语法引用已上传文档，AI 的回答必须在引用处标注原文页码。
5. **AC-5 敏感声明**：所有文档解析输出末尾自动附加："以上内容由 AI 自动生成，仅供参考，不构成投资建议。请结合原始文件独立判断。"

---

### 5.3 基础对话

**用户故事**

> 作为高净值投资者，我希望用自然语言向 AI 提问关于我正在关注的公司，AI 能结合我过去的问题记录和上传的文档给出个性化答案，以便我不需要每次都重新解释背景。

**验收标准（AC）**：

1. **AC-1 首字时延**：对话首个 Token 出现时间 ≤ 2秒（P95，非平均值）。
2. **AC-2 对话历史**：同一会话内的上下文连续，支持至少20轮对话的上下文窗口。用户可以在历史会话列表中查找和恢复之前的对话。
3. **AC-3 记忆调用**：当用户提到"我之前关注的XX公司"、"上次提到的那个逻辑"等指代时，系统自动检索 MemoryOS，若找到相关记录，在回答开头说明"根据您过去的研究记录..."，并引用具体来源。
4. **AC-4 工具调用透明化**：当 AI 调用工具（搜索文档、查询记忆）时，在对话界面中以折叠卡片的形式展示工具调用过程，用户可点击展开查看细节，不展开时不干扰阅读。
5. **AC-5 拒绝无依据预测**：AI 不得对具体股票给出明确的涨跌预测或"买入/卖出"建议。若用户要求，AI 应回答"我可以帮你分析基本面因素，但具体投资决策需要您结合自身情况判断"，并提供分析而非建议。

---

### 5.4 用户体系

**用户故事**

> 作为新注册用户，我希望用邮箱注册后能立即开始使用免费功能，不需要绑定信用卡，以便我在决定付费前能真实体验产品价值。

**验收标准（AC）**：

1. **AC-1 注册流程时长**：从点击"注册"到可以使用核心功能（看信息流、上传文档）的完整流程 ≤ 90秒，包含邮箱验证。
2. **AC-2 免费配额明确**：用户在任何页面都能清晰看到当前剩余配额（今日对话次数、本月文档解析次数），配额耗尽前3次使用时弹出提醒，不是在耗尽时才告知。
3. **AC-3 升级流程**：用户点击"升级专业版"到完成 Stripe 支付全流程 ≤ 3分钟，支付成功后5秒内配额刷新，不需要刷新页面。
4. **AC-4 数据隔离**：通过 RLS 策略确保不同用户的数据（文档、对话、记忆）完全隔离，通过自动化测试验证（尝试跨用户访问数据必须返回403）。
5. **AC-5 注销与数据删除**：用户可申请注销账户，注销后30天内数据完整保留（可撤销），30天后从数据库硬删除，包括向量索引。用户注销时给出明确时间线说明。

## 6. 非功能性需求

### 性能

| 指标 | 目标值 | 备注 |
|------|--------|------|
| 信息流刷新时延 | < 30秒 | 从数据源更新到用户界面刷新 |
| 对话首字时延 | < 2秒（P95） | SSE 第一个 Token |
| 文档解析（100页内） | < 60秒 | 含 OCR 和 AI 提炼 |
| 页面首屏加载 | < 3秒 | LCP，3G网络环境 |
| 并发对话用户 | 支持100并发 | MVP 阶段目标 |
| API 响应时延（非AI） | < 200ms（P99） | 数据库查询类接口 |

### 安全与合规

- **数据隔离**：所有数据库查询强制 Supabase RLS，任何未设置 RLS 的表默认禁止访问
- **传输安全**：全站 HTTPS，WebSocket 使用 WSS
- **金融内容免责声明**：AI 生成的所有涉及证券分析的内容末尾必须附加法律声明，不得省略
- **数据存储合规**：用户数据存储在中国境内服务器（如使用海外 LLM API，确认数据不落盘）
- **付费凭证**：Stripe Webhook 必须验证签名，防止伪造支付成功事件

### 可用性

- **SLA**：核心服务（对话、文档解析）月可用率 ≥ 99.5%，即每月最多允许约3.6小时不可用
- **降级策略**：Claude API 不可用时，自动降级到备用 LLM（Gemini），用户收到通知但服务不中断
- **数据备份**：数据库每日全量备份，向量索引每周备份，备份保留30天

### 可观测性

- LangSmith 追踪所有 AI 调用（prompt、response、token 用量、时延）
- Sentry 捕获所有后端异常，错误率 Dashboard 告警阈值：5分钟内同一接口错误率 > 5%
- 关键业务事件（注册、付费、文档上传、对话开始）通过埋点记录，用于漏斗分析

## 7. 成功指标

### 北极星指标

**月活付费用户数（MAU Paid）**

选择理由：付费 + 月活同时满足，说明用户既认可价值（愿意付钱）又持续使用（没有流失）。这是业务健康度的最核心信号。单纯看注册数和MRR都有盲区，MAU Paid 把两者结合。

### 支撑指标体系

**获客层**：
- 月新注册用户数
- 各渠道获客成本（CAC）：内容营销 vs 口碑 vs 付费投放
- Landing Page 转化率（访问→注册）

**激活层**：
- 注册后3日内完成信息流配置的比例（目标 ≥ 60%）
- 注册后7日内上传第一份文档的比例（目标 ≥ 30%）
- Aha Moment 达成率（收到第一条 AI 日报）

**留存层**：
- D7 / D30 留存率（活跃定义：打开应用 + 有效操作）
- 周活跃天数（目标：付费用户平均 ≥ 4天/周）
- 功能使用深度（仅用信息流 vs 信息流+文档 vs 全功能）

**变现层**：
- 免费→付费转化率（目标第一年 ≥ 8%）
- 月付用户月续费率（目标 ≥ 75%）
- 年付用户年续费率（目标 ≥ 70%）
- 月均 ARPU（平均每付费用户收入）

**口碑层**：
- NPS（每季度调研深度用户，目标 ≥ 50）
- K 因子（1个用户带来的新用户数，目标 ≥ 0.3）

### 预警指标（出现则需立即排查）

- 日报生成失败率 > 5%（feed_worker 稳定性问题）
- 文档解析失败率 > 10%（PerceptOS 解析质量问题）
- 对话首字时延 P95 > 5秒（LLM API 或网络问题）
- 付费用户7日流失率 > 10%（产品价值问题，非获客问题）
